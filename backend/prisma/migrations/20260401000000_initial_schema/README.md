# Provenance note

This migration was hand-authored (not generated by `npx prisma migrate dev`)
because the sandbox that built it cannot reach `binaries.prisma.sh` — Prisma's
CLI needs a query-engine/schema-engine binary from that host for every
operation, including `migrate dev` and `migrate diff`.

It was, however, applied to and verified against a REAL PostgreSQL 16
instance (not mocked): all tables, enums, foreign keys, unique constraints,
and indexes were created with zero errors, and cascade-delete /
uniqueness behavior was exercised directly (see tests/integration/).

Before treating this as your team's source of truth:

```bash
npx prisma migrate dev --name initial_schema
```

on a machine with normal network access. Prisma will detect the schema
already matches (or show a diff if it doesn't) and can reconcile the
migration history properly via `prisma migrate resolve --applied` if needed.
